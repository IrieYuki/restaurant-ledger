# 已知问题与排查记录

本文记录当前版本已观察到的问题。未验证的推测不会写成确定结论。

## 1. 部分中国大陆网络无法访问线上网站

### 影响范围

- 线上地址：[https://restaurant-ledger.rujiangyuxia.workers.dev](https://restaurant-ledger.rujiangyuxia.workers.dev)
- 在部分中国大陆的网络环境中，浏览器无法打开该站点。
- 已测试的手机网络和家庭 Wi-Fi 环境均出现过无法访问的情况。
- 部分测试需要开启 VPN 才能访问。
- GreatFire 对该域名的测试结果显示无法访问；该结果只代表对应测试，不代表所有网络环境都必然无法访问。

### 已进行的排查

1. 使用 `curl -Iv` 访问目标站点时，曾出现 TLS 握手阶段 `Connection reset by peer`。
2. 使用 `--resolve` 指定两个 Cloudflare IP 后，仍出现 TLS 握手连接重置。
3. 强制使用 HTTP/1.1 时，曾出现 TCP 连接超时。
4. 强制使用 TLS 1.2 时，也曾出现 TCP 连接超时。
5. 同一设备、VPN 关闭时，访问 `https://www.cloudflare.com/` 曾成功获得 HTTP 200。
6. DNS 查询结果曾出现不一致：不同 DNS 服务器返回了不同地址；实际 `curl` 连接时又解析到了其他地址。

### 当前判断

上述结果来自不同测试时刻，不能假定每次连接都使用相同 IP。现有证据提示问题可能与 `workers.dev` 域名在部分网络中的可访问性、DNS 解析或网络连接路径有关，但目前尚不能确定具体原因，也不能断言一定是 DNS、TLS、Cloudflare 配置或某一方实施了拦截。

此问题暂未通过修改业务代码处理。修改前端代码不能可靠解决域名可达性或网络路径问题。

### 建议

- 继续在中国大陆不同运营商、不同地区和不同设备网络上做可重复测试，记录时间、DNS 结果、目标 IP 和连接阶段。
- 评估对中国大陆用户更可靠的静态网站托管方案。
- 评估自定义域名、备案要求、部署成本和长期维护成本。
- 迁移前保留当前线上版本，验证新站点的数据隔离、访问方式和回滚方案，避免影响现有用户和本地账目。

## 2. 数据只保存在当前浏览器，缺少多设备同步

### 当前实现

- 账目仅保存在浏览器 IndexedDB 的 `restaurant-ledger` 数据库、`records` object store 中。
- 当前没有使用 `localStorage` 作为备用账本，也没有后端数据库。
- 没有账号登录、云端自动备份、跨设备同步或多人协作功能。
- 应用不会主动上传账目；CSV 和 JSON 都由浏览器直接下载到本地。

### 可能造成的影响

- 更换设备、更换浏览器或使用不同浏览器用户配置时，无法自动看到原来的账本。
- 清理网站数据、卸载浏览器或浏览器回收/阻止本地存储时，账目可能无法恢复。
- 本地数据不是云端数据，也不会自动出现在其它设备上。
- IndexedDB 存储不等同于加密存储，应仅在可信设备上使用。

### CSV 与 JSON 的实际行为

**CSV**

- 历史记录页可导出全部记录或当前筛选结果。
- 包含序号、记录时间、类别、收支方向、金额和备注。
- 使用 UTF-8 BOM，金额保留两位小数；逗号、引号和换行会按 CSV 规则转义。
- CSV 只用于查看和表格处理，当前不支持导入。
- 导出的文件不会上传，但会脱离站点 IndexedDB 保护，仍需按敏感经营数据保管。

**JSON**

- 首页“完整数据备份”可将全部记录导出为带 `format`、`version`、`exportedAt`、`recordCount` 和 `records` 的 JSON 文件。
- 当前备份格式版本为 `1`，单次恢复文件上限为 10 MB。
- 恢复采用合并策略：保留现有记录，只新增不存在的记录 ID；相同 ID 一律跳过，即使内容不同也不覆盖，且不会清空现有数据。
- JSON 可以手动备份和迁移，但不是自动同步，也不是云端备份。

### 建议

- 定期导出 JSON 完整备份，并存放在受保护的位置。
- 在迁移数据前先验证备份文件可读取、记录数量和合并预览是否正确。
- 如需多设备同步，应先完成账号、权限、数据归属、隐私、备份、删除和运维方案设计，再引入后端服务。

## 3. 构建环境问题：Turbopack 子进程权限

### 现象

在本次项目整理时，默认命令 `npm run build` 使用 Turbopack 构建，在处理 Tailwind CSS loader 时失败：

```text
creating new process
binding to a port
Operation not permitted (os error 1)
```

失败发生在当前执行环境的子进程/端口权限环节，不是 TypeScript、ESLint 或页面代码错误。使用同一份源码执行诊断命令 `npx next build --webpack` 后，编译、TypeScript 检查和静态页面生成均成功。

### 当前判断

- 尚未在普通本地终端复现该 Turbopack 错误，因此不能确认它是所有开发环境中的项目缺陷。
- 线上站点此前已有静态导出产物，不能仅凭本次构建失败推断线上部署损坏。
- 这不是本次文档修改引入的问题；`next.config.ts`、Turbopack 和 Tailwind loader 配置在本次整理前已经存在。

### 建议

- 在普通本地终端重新运行 `npm run build`，确认是否仍出现相同错误。
- 如果仅本执行环境失败，应在 CI 或普通终端完成发布构建，并保留当前可用产物。
- 如果普通环境也能稳定复现，再单独创建问题，比较 Turbopack 与 Webpack 构建路径后做最小修改；不要把 `--webpack` 临时诊断命令直接当作永久部署方案。
